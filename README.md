# blockwatch

Наблюдатель за блокировками для роутеров на OpenWrt с [netshift](https://github.com/yandexru45/netshift) или [podkop](https://github.com/itdoginfo/podkop).

Он сам находит сайты, которые у провайдера не открываются напрямую, но открываются через туннель, проверяет каждый опытом и добавляет подтверждённые в список netshift/podkop. Списки, которые вы ведёте вручную, остаются как были: blockwatch дополняет их тем, чего в них не хватает. Соединения при добавлении не рвутся — sing-box перечитывает список на лету.

## Как это работает

**Находит.** Своя таблица nftables только считает признаки, ничего не блокирует и не перенаправляет:

| признак | что видно |
|---|---|
| сброс | сервер присылает RST сразу после приветствия TLS |
| нет ответа | SYN уходит, SYN-ACK не приходит |
| молчит | наши пакеты с данными уходят, обратно — ни одного |
| обрыв | передача началась и замерла, а браузер продолжает переспрашивать |
| обход | медленный обход сайтов, которые в доме уже открывали |

Учитывается только трафик мимо туннеля: то, что уже идёт через netshift/podkop, blockwatch не касается.

**Проверяет.** Подозрение — ещё не блокировка. Для каждого кандидата blockwatch сам делает три запроса: к сайту напрямую, к конкретному адресу напрямую и к тому же адресу через туннель. Блокировкой считается только случай, когда напрямую не отвечают ни сайт, ни адрес, а через туннель страница приходит **целиком**. Передача, оборванная на середине, считается отказом, даже если заголовки успели прийти с кодом 200 — именно так выглядит самая незаметная блокировка. Добавляется находка только после двух таких совпадений в разных проверках.

Имя сайта берётся из журнала запросов dnsmasq — то, которое спросил браузер, даже если ответ пришёл через цепочку CNAME (у сайтов на Vercel, Cloudflare и CDN адрес приходит на служебное имя хостинга). Вердикт хранится на пару «адрес + имя»: за одним адресом хостинга живут сотни сайтов. Если сайт, на котором в трафике был признак блокировки, при проверке не ответил никому, включая туннель, через 15 минут проверка повторяется ещё раз — вдруг туннель сбоил сам.

**Добавляет.** Подтверждённые домены дописываются в `/etc/blockwatch/domains.txt`. Этот файл подключается в netshift/podkop как *Local Domain List*. blockwatch дописывает домен ещё и в уже собранный список sing-box, поэтому новый сайт начинает открываться через пару секунд, без перезапуска.

## Что не делает

- Не видит геоблоки — «сервис недоступен в вашей стране». Для роутера такой сайт выглядит исправным: соединение и TLS проходят, отказ приходит внутри шифрованного ответа.
- Не добавляет российские домены (`.ru`, `.su`, `.рф`) — через зарубежный выход они часто отказывают, — видеоузлы Google и имена ваших собственных серверов из конфига sing-box.
- Не трогает домены, которые уже есть в каком-либо списке netshift/podkop, — ни в туннеле, ни в исключениях. Если YouTube у вас нарочно идёт мимо туннеля, так и останется.
- Не перезапускает netshift/podkop сам и не меняет их настройки. Исключение — команда `blockwatch hook`, которую вы запускаете явно.
- Смотрит только IPv4.

## Требования

- OpenWrt **24.10** или новее (apk и opkg поддерживаются оба)
- netshift или podkop с включённой **загрузкой списков через прокси** (Settings → Download lists via proxy). Через этот служебный вход sing-box blockwatch проверяет, открывается ли сайт через туннель. Можно указать и свой socks-вход — см. «Настройки».
- dnsmasq как DNS-сервер роутера (у netshift и podkop так по умолчанию)

## Установка

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/xDarkOne/blockwatch/main/install.sh)"
```

Установщик сам поставит недостающие `jq` и `curl`, разложит файлы и в конце покажет результат `blockwatch doctor`.

Затем подключите файл доменов к нужной секции netshift/podkop:

```sh
blockwatch hook main
```

Команда один раз перезапустит netshift/podkop, чтобы он собрал список. То же самое можно сделать вручную: секция → *Local Domain Lists* → `/etc/blockwatch/domains.txt` → сохранить.

Смотреть, что происходит: **LuCI → Службы → Blockwatch**.

## Что меняется в системе

| что | зачем | при удалении |
|---|---|---|
| журнал запросов dnsmasq включается | узнать имя сайта по адресу | возвращается как было |
| буфер системного журнала — не меньше 512 КБ (в ОЗУ) | чтобы имена не вытеснялись раньше, чем их прочитают | возвращается как было |
| учёт трафика conntrack (если был выключен) | распознавать обрывы | возвращается как было |
| задание cron раз в 2 минуты | заходы наблюдателя | удаляется |
| таблица nftables `inet blockwatch` | только счётчики | удаляется |

Рабочее состояние хранится в `/tmp`, чтобы не изнашивать флеш. На флеш пишутся только подтверждённые находки и список доменов.

## Команды

```
blockwatch doctor          проверить установку: бэкенд, socks-вход, туннель, проблемы
blockwatch report [all]    найденные блокировки (all — вместе с живыми и лежащими)
blockwatch hook [секция]   подключить файл доменов к netshift/podkop
blockwatch unhook          отключить
blockwatch export          перенести подтверждённое прямо сейчас
```

Журнал находок: `/etc/blockwatch/blockwatch.log`.

## Настройки

`/etc/config/blockwatch`:

| параметр | по умолчанию | |
|---|---|---|
| `enabled` | `1` | выключить заходы |
| `backend` | `auto` | `netshift`, `podkop` или автоопределение |
| `auto_export` | `1` | `0` — только находить, ничего не добавлять |
| `max_per_day` | `30` | предел добавлений в сутки |
| `never_suffix` | `ru su xn--p1ai googlevideo.com gvt1.com` | что не добавлять никогда |
| `socks`, `dns`, `fakeip_range`, `fakeip_mark` | из настроек бэкенда | ручная настройка, если автоопределение не справилось |

Всё, чем netshift и podkop отличаются друг от друга, — имена таблиц, метки, адреса — blockwatch читает из их собственного `constants.sh` и конфига sing-box.

## Удаление

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/xDarkOne/blockwatch/main/install.sh)" -- uninstall
```

Список доменов и журнал останутся в `/etc/blockwatch`. Чтобы убрать всё, включая подключение к netshift/podkop, добавьте `--purge`.

## Проверка

`tests/run-rootfs.sh 24.10` и `tests/run-rootfs.sh 25.12` прогоняют установку, распознавание netshift и podkop, подключение и удаление в корневой ФС OpenWrt соответствующей версии. То же самое выполняется в CI при каждом изменении.
